# 历史净化与版本追溯

2026-10-20，经项目所有者授权，对本仓库两个分支、两个 Alpha 标签及其全部可达历史进行统一净化。本次是已发布标签不可移动规则的明确例外，不是应用版本发布。

## 范围与核验

- 检查改写前 3,415 个提交、12,161 个文件内容对象，合计 175,295,530 字节。
- 清除历史固定会话 Cookie、认证令牌、固定登录口令、客户端 API 密钥与旧客户端配置中的 API key 字面量，以明确的失效占位文本替代；没有尝试登录或验证这些凭据是否有效。
- 删除 20 条历史路径：9 个构建缓存文件、6 个测试文件、5 张已弃用截图。此前移除的 191 项个人开发规则、工具、测试工程和核验档案仍未出现在可达历史中。
- 清理与本应用无关的仓库参考文字。实际使用的源码、字体、图标、渲染依赖及其许可和作者致谢继续保留。
- 保留全部 3,415 个历史提交节点、作者、提交者、日期、时区和父子关系。改写产生 3,415 个新编号；1,714 个原带签名提交无法保留有效原签名，净化副本不宣称具有原签名。
- 逐提交重算并核对完整文件树：所有差异均为指定路径移除、凭据替换、无关引用及已删除图片链接清理。已知待清理凭据和无关引用在净化后的可达对象中均为零。
- 当前 410 个正式应用源码和资源文件保持不变；此次新增的仓库说明、编号映射和展示图作为后续文档提交记录。

## 协作者迁移

先另存自己的未提交修改和本地工作，然后重新克隆本仓库，仅迁移需要的代码差异。不要将旧分支或旧标签合并、推送回来，也不要推送旧镜像或备份 bundle，否则可能恢复已清理内容。日常提交继续采用英文短类别前缀，例如 `app:`、`docs:`、`history:`、`release:`。

```sh
git clone https://github.com/GoodNima/DanXi_HarmonyOS.git
```

改写前完整备份与私有审查资料仅保存在维护者本机，不在公开仓库建立旧历史备份分支或标签。

## 公开范围与残留边界

本次清理覆盖本仓库可控制的分支和标签。上游仓库、外部 fork、他人克隆、GitHub 按旧编号提供的对象和缓存不受此次推送控制；不能将可达历史净化表述为旧对象已从互联网永久删除。

2026-10-20 推送后实测：GitHub 按旧编号读取旧提交和一个历史敏感文件对象仍返回 HTTP 200。它们已经不在当前四个引用的可达历史中，但服务端仍保留对象。远端当前 main 的 442 个文件已逐个核对，两个 Release 的四个附件重新下载后校验值与原包相同；仓库没有 Pull Request、Actions 运行、构建附件或缓存等待清理。

凭据删除不等于撤销权限。历史凭据的所有者仍需在对应服务撤销或轮换可能有效的值；本次没有其服务端管理权限，也未测试有效性。真正敏感的 GitHub 缓存与只读引用可通过 GitHub Support 申请处理；是否受理取决于其政策及上游/fork 残留情况。非敏感旧文件通常不属于支持团队清除缓存的范围。

依据：[GitHub 敏感数据删除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
